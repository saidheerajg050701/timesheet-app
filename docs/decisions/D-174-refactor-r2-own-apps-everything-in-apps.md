# D-174: Refactor R2 – own apps; everything in apps/

- **Status:** Accepted
- **Area:** Layout
- **From:** Refactor R2 – Own apps; everything in apps/ (commit `6421d8e`)
- **Recorded:** 2026-10-30

## Context

A decision in the **Layout** area, recorded during Refactor R2 – Own apps; everything in apps/. It affects these parts of the specification: D-173, B.6.

## Decision

**Refactor R2 – own apps; everything in `apps/`** (no behaviour change). **Apps:** `apps/directory` (people, accounts, permissions, employee admin, importer, demo seed), `apps/timesheets` (weeks, grid, change requests, approvals), **`apps/projects`** (Project, Task, the allowed-task link and the budget fields with `services/projects.py`, `tasks.py`, `project_admin.py` and the Project/Task admin), **`apps/compensation`** (PayRecord with `services/pay.py`, `pay_import.py` and `access.py` — `can_manage_pay`, `can_see_costs`, `can_see_everyones_costs` — and `PayAdminMixin`, which the Employee admin uses so the Pay pages keep their addresses and URL names), `apps/payroll`, `apps/audit`, `apps/analytics` (Dashboard and Team only) and **`apps/reports`** (Project hours and Project budget: services, views, URLs, templates, JS, `time_project_report`). Each `apps.py` sets `name = "apps.<app>"` and keeps `label = "<app>"`, so `AUTH_USER_MODEL = "directory.User"`, table names, migration history, the payroll router (label "payroll") and audit entity names are unchanged; code imports `apps.<app>…`. **Moving models without moving data:** the moved models keep their tables through `Meta.db_table` (`timesheets_project`, `timesheets_task`, `timesheets_project_tasks`, `directory_payrecord`), and four migrations are state-only (`SeparateDatabaseAndState` with no database operations): `projects/0001_initial` and `compensation/0001_initial` create the models in Django's state; `timesheets/0010_move_projects` points `TimeEntry.project` / `.task` at `projects.*` and drops Project/Task from timesheets' state; `directory/0004_move_payrecord` drops PayRecord from directory's state. They run no SQL; an existing database only records them (proved on a seeded test database: schema and every data table's rows identical before, after and on re-apply; only Django's content-type and permission bookkeeping gains rows for the new labels). `directory/0001` now imports `apps.directory.managers` (one-line path fix, no schema change). **Templates and JS per app:** `apps/<app>/templates/<app>/…` (same template names) and `apps/<app>/static/<app>/…` (`timesheets/grid.js`, `timesheets/countdown.js`, `projects/project_search.js`, `analytics/dashboard.js`, `analytics/team.js`, `reports/report.js`, `reports/budget.js`); site-wide stay in `templates/` (base, 403/404/500, includes, registration, admin/base_site) and `static/` (`css/theme.css`, `vendor/`). **Accepted address changes:** Project/Task Admin pages `/admin/projects/…` (Admin → Projects) and the JS file addresses above; every app page, URL and URL name is unchanged. **Tests:** `tests/projects/`, `tests/compensation/`, `tests/reports/`; old data-migration functions are tested with `tests.factories.MIGRATION_APPS` (today's models under the labels those migrations ask for).

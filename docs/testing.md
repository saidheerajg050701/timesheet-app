# Testing

How the app is tested, how to run the tests, and every catalogued test (T-01 … T-270)
with what it checks, where it lives and its status. Tests never touch your real databases.

**Latest full run** (`bash scripts/test_all.sh`, October 30, 2026, after Refactor R2): **350
tests, all passing** — 326 unit + integration, 24 browser (e2e); parametrised cases counted
separately. Coverage of unit + integration tests: **98.27 %** (the script fails below 80 %).
The 270 catalogued tests are the ones with an ID; the rest are small helper checks
without one (D-17).

## How to run

```bash
make test         # everything, in order (= bash scripts/test_all.sh): ruff, no forgotten
                  # migrations, Django check, unit + integration with coverage, browser tests
make test-fast    # unit + integration only (uv run pytest -m "not e2e"), about a minute
make e2e          # browser tests only (uv run pytest -m e2e)
make lint         # ruff
uv run pytest tests/timesheets              # one app's tests
uv run pytest -k grid                       # tests whose name contains "grid"
uv run pytest -m "not e2e" --cov --cov-report=html   # coverage report → open htmlcov/index.html
bash scripts/test_all.sh --browser-channel chrome    # browser tests with your installed Google Chrome
```

The browser tests need Chromium once: `uv run playwright install chromium`.

`scripts/test_all.sh` runs, in order, and stops at the first failure:
1. `uv run ruff check .` — code style and common bugs
2. `uv run python manage.py makemigrations --check --dry-run` — no forgotten migrations
3. `uv run python manage.py check` — Django configuration
4. `uv run pytest -m "not e2e" --cov --cov-fail-under=80` — unit + integration with coverage
5. `uv run pytest -m e2e` — browser tests, mandatory (D-95): "no tests collected" fails too

Run it before every commit (see [CONTRIBUTING](../CONTRIBUTING.md)).

## Layers

| Layer | What it checks | Tools | Speed |
|---|---|---|---|
| **Unit tests** | Single functions: deadline maths, hour splitting, permissions, sign-up rules | pytest, time-machine | Milliseconds each |
| **Integration tests** | Views + database together: submit a week, approve a period, payroll record appears | pytest-django, Django test client, factory_boy | Fast |
| **End-to-end (E2E) tests** | A real browser clicks through the app like a user | Playwright for Python | Slower (run before committing) |
| **Manual acceptance tests** | You click through the checklist in D.1 | Your browser + demo logins | — |

## Test databases are separate

`pytest` automatically creates **temporary test databases** (for both `default` and `payroll`) and deletes them afterwards. Running tests **never touches** your real `db.sqlite3` or `payroll.sqlite3`. Tests that use the payroll database declare `@pytest.mark.django_db(databases=["default", "payroll"])`. The tests use the `config.settings.test` settings (set in `pyproject.toml`) and a fixed
clock (time-machine), so dates and deadlines are always the same.

## Writing a new test

- Put it in the app's folder: `tests/<app>/unit/` for a pure rule, `tests/<app>/integration/`
  for pages and the database, `tests/site/` for whole-site checks, `tests/e2e/test_<area>.py`
  for a real browser (shared helpers in `tests/e2e/helpers.py`).
- Use the shared fixtures in `tests/conftest.py` (a small company `org`, `login_as`,
  `make_week`, `fixed_now`, …) and the factories in `tests/factories.py`.
- If it checks a rule, give it the next ID (**T-271**, …): its docstring starts with the ID, e.g.
  `"""T-271: …"""` (D-16, D-17), and add a row to the table below in the same change.

## Coverage targets

- `*/services/*` (business rules): **≥ 90%** line coverage
- Whole project: **≥ 80%**
- Report: `uv run pytest --cov --cov-report=html` → open `htmlcov/index.html`
